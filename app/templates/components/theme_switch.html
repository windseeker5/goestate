{# Appearance control: a Light / Dark / System segmented radio group. Why native radios rather than styled buttons: a single-choice control gets correct arrow-key navigation and screen-reader semantics for free from a fieldset + radio group. Hand-rolled aria-pressed buttons would need JS to reimplement both. The inputs are visually hidden (sr-only) but still focusable, and Tailwind's has-[:checked]: variant paints the selected state straight from the input, so no JS is involved in the appearance at all. The inputs render unchecked: the value lives in localStorage, which the server cannot see. window.estateTheme (static/js/app.js) ticks the right one on load and listens for changes — it is the only thing that may write the stored value.
