Set align="end" on any column whose cells are right-aligned (e.g. currency, or an actions column) so the header lines up with the data instead of staying left-aligned while the column reads right — that mismatch is what makes a table look "wrong". rows {list} Row data; caller renders the cells. sort {string} Current sort column key. order {string} "asc" | "desc". base_url {string} URL prefix for sort links (appends ?sort=KEY&order=asc/desc). caption {string} Optional table caption. scrollable {bool} Default true. Wraps the table in a horizontally scrollable container (.table-container) for wide tables on narrow screens. Set to false if any row uses a Basecoat popover-based component (dropdown-menu, select, combobox, popover) — see the "Popover clipping" note below. Popover clipping gotcha: Basecoat hides a *closed* popover with opacity:0 + scale (for the open/close transition), not display:none, so it still occupies real layout space at all times, positioned via `top: 100%` relative to its trigger. Per the CSS spec, any `overflow: auto`/`hidden` ancestor (which .table-container is, by design, for responsive wide tables) clips absolutely-positioned descendants that extend past its bounds — so a dropdown-menu/select/combobox/popover placed in any column of a scrollable table gets silently clipped the instant it opens, even though nothing is actually scrolled. If a row action needs one of those components (e.g. components/action_menu.html), pass scrollable=false (only safe if the table's columns don't actually need horizontal scroll on narrow screens). #} {% macro data_table(columns, rows, sort=None, order="asc", base_url="", caption=None, scrollable=true) %} {# rounded-lg border + bg-background wrapper: matches the bordered card look every component gets in the UI Gallery demo (see gallery/ components.html's `section()` helper), so a real table in the app looks identical to its gallery preview instead of rendering as a bare, borderless table. IMPORTANT: no overflow-hidden here, even though it would look slightly cleaner clipping the table's square corners to the container's rounded ones. scrollable=false tables use overflow-x-visible specifically so a row's action_menu popover (dropdown-menu) isn't clipped when it opens — see the "Popover clipping" note above. overflow-hidden would silently reintroduce that exact bug for every scrollable=false table.
